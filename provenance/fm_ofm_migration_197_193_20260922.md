# FM-OFM guidance refinement migration (2026-09-22)

User explicitly requested server197 and server193 because server216 was overloaded;
this supersedes the earlier instruction excluding server193 for this task.

Scope: round-two FM-OFM guidance refinement only. The native OFM completion and
numerical-repair jobs on server216 are independent and remain untouched.

Assignments (two named tmux workers per host; one worker per GPU):

- server197, two A100 80 GB: NS forward/inverse and Burgers trajectory completion.
- server193, two RTX 4090 24 GB: Poisson forward/inverse, Helmholtz forward/inverse,
  and Darcy inverse.

Eight server216 refinement controllers were suspended to stop new launches, their
active sampler children were allowed to finish, and all five completed but
not-yet-audited trials were independently validated. The controllers were then
terminated. No completed trial was discarded or resampled. Original records remain
on server216. Each destination receives byte-identical completed trials, pinned
operator weights, test tensors/normalization, and prepared disjoint validation
assets. `migration_inventory_server*.json` lists every transferred file's size and
SHA256; `migration_verified.json` records verification and localized manifest
hashes. Original validation manifests are preserved as `manifest.server216.json`.
Reference `run.json` files remain unchanged; only new launches map input paths.

Official repositories remain at the same pinned Git revisions. Training, sampling
algorithms, model weights, observation masks, seeds, step counts, and the frozen
parameter search plan are unchanged. New records capture each host's actual Python,
Torch/CUDA, package versions, input hashes, and official source revisions.

Both destination hosts have busy CPU queues but idle GPUs. Each worker and sampler
uses one OpenMP/OpenBLAS/MKL thread and nice 19. The global CPU load threshold is
replaced by a full-schedule, two-case GPU preflight, followed by one process per GPU.
Minimum free GPU memory is 32 GiB on server197 and 16 GiB on server193; the measured
peak must fit that limit before launch. GPU utilization admission remains enabled.
The controller records runtime, logs, and exit status in its named output folder.

The original command still refreshes the comparison:

```bash
python3 ~/C01Python/DDIS_comparison_20260919/adapters/fm_ofm_strength_study.py --fetch
```

It reads the original baseline on server216 and overlays each destination's assigned
round-two groups. Live PIDs are checked on the owning host. Host reports are merged
without double counting; partial trials cannot replace a complete result. This
updates the guidance study report, not the separate seven-method main comparison.
